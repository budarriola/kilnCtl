# Review KG-01 page gate (2026-10-19)

Scope: origin/dev f39d5a9d5 (central page gate: a denied page-shell GET gets a 302 to `/?next=<page>`; dashboard sign-in first) and 9db23af70 (KNOWN_ISSUES).
Result: HIGH 0, MED 0, LOW 3, INFO 5. The gate meets the owner's intent: with auth on, a logged-out viewer gets only the dashboard, login and shared assets.

## Findings

- **KH-01** LOW: protected page shells served to a signed-in admin have no `Cache-Control: no-store` (only the 302 has it). After logout or expiry, Back/Forward (bfcache) or history can show the page content again without asking the server. Fix: set `no-store` on every page-shell response (for example in the prehandler ALLOW branch when `is_page_shell_get(ctx)`).
- **KH-02** LOW: app.js `kcNextTried` loop guard is set when a signed-in admin follows `?next=`, but it is cleared only after a dialog sign-in. A second `/?next=<same page>` in the same tab while signed in (a bookmark, or a 302 after a short server-side refusal) leaves the user on the dashboard with no message. Fix: clear it once the target page loads, or store a timestamp.
- **KH-03** LOW: the prehandler wiring is checked only by regex (check_page_gate.ps1 part C). No host test runs `kiln_http_prehandler`/`send_page_gate_redirect` to check the 302 status, `Location` and `no-store` together, and the live check is BENCH-PENDING. The pure helpers (`http_auth_page_gate_location`, tier/decision tables) and the JS flows are covered well.
- **KH-04** INFO: `Location` is built from the registered `ctx->uri`, not the request, so a query string is dropped (`/settings?x=1` comes back as `/?next=/settings`). The hash is kept on the client only. This is safe (no injection), and deep-link state is lost.
- **KH-05** INFO, no bypass found. URIs are matched exactly (no `uri_match_fn`/wildcard routes), so a trailing slash, other case, `//`, `%2F` or an unknown path finds no handler. `captive_portal_404_handler` then answers 302 to `/` (or JSON 404 for `/api/`). HEAD is not registered for page shells. Only `/`, `/login`, `/app.js`, `/nav.js`, `/theme.css` and `/status` are OPEN non-API GETs. check_page_gate part A pins that list. `/commissioning_shared.js` is now ADMIN.
- **KH-06** INFO, no open redirect. The server `Location` uses the charset `[A-Za-z0-9_/]` from the route table. The client `kcSafeNextPath` requires the same charset after decoding and refuses `//`, `/` and `/api/`. No redirect loop: a page shell never redirects to another page shell, and the admin case has a guard (see KH-02).
- **KH-07** INFO: other paths are kept. Auth off: ALLOW before the gate. Unprovisioned `/wifi`: WIFI_SETUP ALLOW, and once provisioned it is gated like any other page. Bootstrap: the dashboard sends it to the bootstrap form through `ensureAdminLogin`. TOTP reset is API-only and unchanged. The recovery image runs its own server and is untouched. INSUFFICIENT (signed-in USER): 302 to the dashboard, where the dialog asks for an admin sign-in; the link gate also catches role `user`. JSON/API routes keep 401 / 403 `insufficient_role` (`is_page_shell_get` excludes `/api/`; `/scan` and `/networks` are not shells).
- **KH-08** INFO, URI cap and RAM: no routes were added, so the URI cap is unchanged. The cost is one 64 B stack buffer on the httpd task and about 80 lines of app.js. The JS test is picked up by check_page_js_tests.ps1 (test_*.js glob), and check_page_gate.ps1 by the run_all_checks check_*.ps1 glob.
