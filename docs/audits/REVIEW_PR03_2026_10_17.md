# REVIEW_PR03_2026_10_17

Scope: 8644039d1 (PR-03/PQ-02: `boot_id_unseen` starts true; `heat_enable_assume_boot_id_seen_for_host_tests()`), docs 0129d810f, f02bfe357.
Counts: HIGH 0, MED 1, LOW 1, INFO 2. Fixes: 4e94dfcac.

## Production boot path (no deadlock)
`safety_poll_task` guard tick (`profile_executor.c` ~2629), only when the status read succeeds:
`heat_enable_note_boot_id_seen(pico_boot_id_ever_seen)`, then `heat_enable_note_pico_boot()`, then pico state, then
`heat_enable_reconcile()` last. With `boot_id_unseen` true at init, acquire withholds (sets `pending`), note_pico_boot
returns early, reconcile does not retry. First sight sets `reboot_verdict_pending` and clears `boot_id_unseen`.
No claim: the next DIAG since reboot resolves the verdict, and a later acquire is granted. Claim held: see PZ-02.
After the fix the held claim is classified by the first DIAG and reconcile then sends enable (host test asserts one
enable send after a benign DIAG). A Pico that never reports a boot id stays cold by design, with the PR-04 pause reason.

## Findings
- **PZ-01** LOW, `heat_enable.c:971`, `heat_enable.h:298`. `heat_enable_assume_boot_id_seen_for_host_tests()` had no
  compile guard, so production code could call it and skip both the PR-03 fail-closed default and the PR-01 first-sight
  rule. No production caller exists today. Fixed (4e94dfcac): declaration and definition sit under
  `#ifdef KILNCTL_HEAT_ENABLE_TEST_HOOK`, defined only in the host rsp (`build_host_tests.ps1`). The target CMake never
  defines it, so a target call fails to compile (C4013-style implicit declaration) or link.
- **PZ-02** MED, `heat_enable.c:951`. PQ-02 was not fixed by 8644039d1. A claim taken while the boot id was unseen
  keeps `held_mask` set. On first sight only `reboot_verdict_pending` was set; acquire's `was_empty` re-arm never runs
  for a held claim, and note_pico_boot only classifies when `reboot_classify_pending` is set. So the same guard tick's
  `heat_enable_reconcile()` sent enable before any DIAG, and a Pico WATCHDOG/ASSERT boot reason at ESP boot (the PR-01
  case) was skipped for that claim. The 8644039d1 test missed it because it never called reconcile. Fixed (4e94dfcac):
  first sight with a held claim sets `reboot_classify_pending` and `reboot_had_claim`. Test extends
  `test_pr03_default_unseen` (reconcile before DIAG sends nothing; benign DIAG then reconcile sends once). Negtest:
  removing the re-arm is CAUGHT by assertions at test_heat_enable.c:1523/1524 (mutant compiled).
- **PZ-03** INFO. PR-05 accept is sound: with `boot_id_unseen` true, `note_pico_boot` returns before setting
  `reboot_seq_known`, so the baseline is the first post-sight seq, and no claim can be granted before then.
- **PZ-04** INFO. PR-07 accept is sound: the first-sight reset of `diag_since_reboot` without a seq bump is only read by
  the guard tick as "DIAG for this boot"; nothing keys on the seq for it, and clearing it only delays classification
  (fail closed). The stale "boot_id_unseen starts false" comment at the PQ-01 block was corrected.
