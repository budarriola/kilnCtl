## Deliverable 0 — `tools/worktree_mint.ps1 -RunSetup`

**The gap.** `_2026-09-16b.md`'s "Full-suite run" section could not get
`tools/run_all_checks.ps1` to completion in its worktree: a freshly minted
worktree has no `tools/PcTools/.venv` (gitignored, generated by
`tools/setup.ps1`), so the runner's PC-side selfcheck step fails closed
(`selfcheck.py ... not found`) before reaching any gate. That cost the
previous pass its full-suite evidence entirely.

**The fix.** Added a `-RunSetup` switch to `tools/worktree_mint.ps1`: after
minting, it runs `tools\setup.ps1` inside the new worktree (`powershell
-ExecutionPolicy Bypass -File <worktree>\tools\setup.ps1`) and prints `SETUP:
ok` or `SETUP: FAILED (...)`. A setup failure does not fail the mint itself —
the checkout succeeded regardless — but is loud and greppable rather than
silently missing. See `tools/worktree_mint.ps1`'s own updated header comment
for the full rationale.

**Negative test (behavioral, not "the flag doesn't exist yet").** Two
separate worktrees minted from the same commit:

- `tools\worktree_mint.ps1 -Label gates0916c` (no switch) → then, inside it,
  `tools\run_all_checks.ps1 -Only "selfcheck_nonexistent_wont_match"`:
  ```
  FAILED: expected C:\wt\gates0916c_iepkuf\tools\PcTools\selfcheck.py (or its
  venv C:\wt\gates0916c_iepkuf\tools\PcTools\.venv\Scripts\python.exe) not
  found -- has it moved? A missing selfcheck.py must not read as a clean run.
  Pass -AllowFewerChecks if a partial tree is genuinely intended.
  ```
  Exit code 2. Confirms the parent behavior this fix targets: an unprovisioned
  worktree fails closed before any gate runs.

- `tools\worktree_mint.ps1 -Label gates0916cs -RunSetup` → `SETUP: ok`
  printed (uv-provisioned venv, `kilnctrl` import confirmed) → same
  `run_all_checks.ps1 -Only "selfcheck_nonexistent_wont_match"` in that
  worktree:
  ```
  Running 0 guard scripts from C:\wt\gates0916cs_a4yx4z (parallel, throttle 8)
  0 passed, 0 skipped, 0 failed.
  ```
  Exit 0 — the PC-side selfcheck gate is cleared (0 matched by the
  deliberately-nonexistent filter, but the selfcheck itself, which runs
  before any glob filtering, no longer fails closed). This is the same
  commit tree as the failing case above; the only variable is `-RunSetup`.

The `gates0916cs_a4yx4z` worktree was removed after this test
(`tools\worktree_mint.ps1 -Remove -Path ... -Force`, no changes to discard).
The main work continued in `gates0916c_iepkuf`, which had `tools\setup.ps1`
run in it directly afterward (equivalent effect, so the rest of this
document's gates could be measured against a fully provisioned tree).
