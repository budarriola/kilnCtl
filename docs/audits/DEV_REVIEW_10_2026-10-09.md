## LOW-1: two gate-evidence rows split by a mangled `\n`, and the table check cannot see it

`docs/audits/GATE_NEGATIVE_TEST_EVIDENCE.md:51-52` and `:108-109` (added in `26762159`): the
text `tools\negtest.ps1` was written through an escape-interpreting path. `\n` became a
newline, so each row reads `...tools` and continues on a new line starting with
`egtest.ps1 -Command ...`.

Failure scenarios:
- The recorded negative-test commands cannot be copied and rerun.
- The continuation line is not a table row, so the mutation/result text is outside the table.
- `check_gate_negative_test_table.ps1` still passes, because it only parses lines that start with `|`. Any similarly broken row would land silently.

Fix:
- Restore `tools\negtest.ps1` on both rows, joining each back into one line.
- Make the check fail on any non-blank line inside the table region that does not start with `|`.
- Negative-test that new rule with `tools\negtest.ps1 -Preset check`.

## LOW-5: gzip decode errors still mapped inconsistently after `121d9604`

`121d9604` added `BodyDecodeError` and maps a bad gzip body to `(None, reason)` in
`_http_get_raw_authed` only. Three paths still differ:

1. `tools/PcTools/src/kilnctrl/bench_test/cases_web_rw.py:441-449` (`_SecHttpClient._get`): on a decode failure it returns `(200, None, headers)`. A judge that checks the status and then parses the body treats a transport glitch as a firmware defect and reports FAIL instead of INCONCLUSIVE.
2. `tools/PcTools/src/kilnctrl/bench_test/cases_web.py:101-102`: `gzip.decompress` is not guarded. `zlib.error` is not an `OSError` subclass, so the `except (URLError, OSError)` at line 106 does not catch it. A corrupt deflate stream raises out of the case as an unhandled exception.
3. `cases_web_rw.py:153`: in the `HTTPError` branch, a bad gzip error body returns `(None, str(dexc))`. That discards a real HTTP status such as the 409 or 403 refusal the judge is asserting on. The judge then reports INCONCLUSIVE ("no status") for a response that did carry a decisive status.

Fix:
- Route all three through `_decode_body` with one mapping: success returns `(status, body)`; a decode failure on 2xx returns `(None, reason)`.
- In the `HTTPError` branch, keep `exc.code` and set the body to None.
- Add a unit test per path that feeds a truncated gzip body.
