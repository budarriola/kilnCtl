# HANGFX1 (2026-10-12): check_land / test_host_fakes "hangs"

## Root cause
- test_host_fakes.ps1: every compile and run used `cmd /c ... 2>&1` captured through a PowerShell pipe. cl.exe leaves a
  detached `vctip.exe` (VC telemetry) holding the pipe write end after its parent exits, so the capture blocked until
  vctip died (observed: orphan VCTIP.EXE with a dead parent). Each compile also re-ran vcvarsall.bat (~25 times), which
  under 100% CPU load took minutes. There is no infinite loop in fake_wdt.c or test_fake_wdt.c (no loops at all); the
  "hang at the wdt negative" was the pipe wait plus load.
- check_land.ps1 is NOT hung: it prints every case, then exits 0. It simply spawns ~65 land.ps1 processes; measured
  15 min (rc=0) on a 100% CPU machine (powershell start 2.2 s, git status 1.4 s), against the 900 s cap. Baseline under
  negtest: 729 s. Not fixed here beyond the classification below; it needs sharding or a lighter harness if load persists.

## Fixes
- test_host_fakes.ps1: output goes to a file (no pipe handle to inherit), bounded wait (300 s compile / 60 s run) with
  `taskkill /T` of the child tree, VSCMD_SKIP_SENDTELEMETRY=1, vcvarsall imported once per run. Result: 74 s, then 205 s
  as a negtest baseline under the same load, pass=1209 fail=0.
- land.ps1: run_all_checks' `FAIL <check> (timed out: killed after exceeding 900s wall-clock cap)` now parses as a FAIL
  for that check (code "timeout", matching the section header `(exit timeout)`), so it is classified NEW or KNOWN
  and is refused unless explicitly allowed. check_land.ps1 gained a case for it.

## Negtests
- check_land: reverting the regex to `(?:exit|killed)` -> CAUGHT by the new assertions.
- test_host_fakes: discarding captured output -> CAUGHT (no RESULT lines).
