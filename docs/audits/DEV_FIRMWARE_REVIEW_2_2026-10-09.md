# Dev firmware review 2 (2026-10-09)

Scope: commits on `origin/dev`:

- `290db19e`: relay_cycles in backup export and import
- `46616a4e`: `recovery_mode` moved to `/api/status`, and `/api/ota/esp/status` made ADMIN
- `74c7265a`: profiles rev-floor fix for HIGH-1, HIGH-2 and MED-1
- `3d9af536`: factory reset erases the legacy default-partition NVS keys, and the relay_cycles migration erases the old copy once the new copy verifies
- `748e1bec`: pref_cfg_fs probe for a newer file with the wrong size
- `d327138a`

Each claim below was checked by reading the code at `origin/dev` (`5f467293`). The commit messages were not taken on trust. Line numbers are at that tip. The earlier review is `docs/audits/DEV_FIRMWARE_REVIEW_2026-10-09.md`.

Review focus: data loss on the boot, migration and reset paths; partial-failure handling; lock order; httpd handler stack use; tests that cannot fail.

| 2 | MEDIUM | `firmware/KilnFW/App/drivers/http/profiles_http.c:903-1010`, `1052-1057`, `1094-1095` | **Once the rev floor is unknown, every profile slot is refused for good.** `slot_rev_unknown[id] = !rev_floors_known` now covers every slot, not just slots with no file (this widens the "only blocks saves into slots that have no file" scope of the earlier review). ## Checked and found clean

- **d327138a.** `note_oversized_nvs_blob()` (`iter_tune_store.c:122-140`) now uses `persist_scratch_alloc`, and the include was added. This closes M1 from the earlier review.
- **748e1bec, iter_tune path.** When the probe hits, NVS serves that boot and the cfg file is left untouched. It is never migrated or rewritten.
- **74c7265a, `nvs_erase_slot`.** It reads into a zeroed `persist_scratch_alloc` buffer, so a short legacy array is zero-extended correctly. The diagnostic reader memsets its scratch. A bad or unreadable `profN` blob now passes rev 0 to resolve and raises `s_profile_rev` to the trusted floor. The extra `bool[100]` is on the boot-only `nvs_load_all_from` stack, not an httpd handler. The tests were updated consistently and can fail.
- **290db19e, validation.** `hw_relays` must equal `KILN_IO_RELAY_COUNT`. Each `c<i>` must be an integer in `[0, RELAY_CYCLES_RESTORE_MAX_COUNT]`. Validation runs in pass 1, before any commit.
- **3d9af536, relay_cycles migration.** It runs only into an empty kiln_nvs, under `s_rc.lock`. The legacy erase follows only a read-back and memcmp verify. In factory reset, the legacy erase runs first; its errors propagate to `first_err`, and the partition erase still proceeds.
- **46616a4e.** The worst-case `/api/status` JSON render test was updated for the new field. The PC `ota_http_client.get_esp_status` goes through `http_auth.urlopen`, which logs in on a 401.
- No new lock-order inversions were found. The new NVS work runs under `s_rc.lock` alone or on the boot path, and the factory-reset legacy erase runs on `bx_flash_worker` (10240 B internal stack) with only small static key arrays.
