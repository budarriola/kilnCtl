## LOW-1: a string literal containing `/*` or `//` hides every site after it (new throw bypassed)

`tools/check_stack_margin_registration.ps1:106-142`. `Get-CodeOnlyLines` strips comments without
tracking string literals. A `"/*"` inside a string opens a fake block comment that runs to the next
`*/`. A `"//"` inside a string (for example `"http://"`) truncates the rest of that line.

Mutant C4 adds this after the `recovery_exit` register:

```
ESP_LOGI(OTA_HTTP_TAG, "see /api/ota/*");
xTaskCreate(ota_recovery_exit_reboot_task, "recovery_exit_reboot", 4096, ...);
ESP_LOGI(OTA_HTTP_TAG, "*/");
```

It was MISSED (the check exited 0): a 4096 B create beside a 2048 B registration, and nothing reported it.

**This already happens in today's tree.** `main_network_http.c:560` logs `"... no /api/logs/* endpoints ..."`. Everything from
there to the next `*/` is blanked, including the `ota_confirm` create at `main_network_http.c:766`. I
scanned all of `drivers/`, `App/*.c` and `hwAbstraction/esp`, and that is the only site hidden today.
The `ota_confirm` entry in `$exemptCreatedNames` (`:560`) is therefore dead: deleting it still passes.

**Failure scenario:** a task created in that region with an unregistered or mismatched size passes the
name check and the size check silently.

**Fix:** skip `"..."` and `'...'` literals (handling `\` escapes) before looking for `//` and `/*`. The
helper is duplicated in `check_uri_handler_cap.ps1`, `check_bridge_reject_reason.ps1` and
`check_uart_version_independence.ps1` and needs the same fix there.

## LOW-2: a create site whose first argument is not a bare identifier is invisible to both sub-checks

`check_stack_margin_registration.ps1:531` (`$createPattern2`) and `:680` (`$createStackRe`) require
`xTaskCreate*(<identifier>, "name", ...`. Mutant C3 adds a second create,
`xTaskCreate((TaskFunction_t)ota_recovery_exit_reboot_task, "recovery_exit_reboot", 4096, ...)`. It
was MISSED: the name check and the size check both skip it. The same applies to `&fn` and
`(void *)fn`.

**Failure scenario:** a second creation path for an existing task, with a cast task function and a
different stack, gets past the LOW-3 fix. No such site exists today.

**Fix:** accept any first argument up to the first top-level comma, for example
`xTaskCreate\w*\s*\(\s*[^,"]+?\s*,\s*"`. Also count every `xTaskCreate\w*\s*\(` in code and fail if
the number of matched sites differs.

## INFO-1: the skip ratchet compares names only, not reasons

`:735-741`. `$stackSkipAllowed`'s reasons are prose. A name that is already skipped can change why it
is skipped without failing the check. For example, `monitor_task` could gain a register call with an
unevaluable size: it moves from "create site only" to "sizeof", and the ratchet still passes. To
enforce the reasons, store the reason class (`create-only`, `register-only`, `unevaluable`) and
compare it as well.

## INFO-2: the i2c/spi owner pairs are still not compared

LCD19FX4 LOW-4 asked for an alias map covering more than `recovery_exit` (its text reads "..."). The
fix aliased only `recovery_exit`. The i2c owner sizes are literal at the callers:
`i2c_owner_init(..., 4096, ...)` at `SX1509.c:421` against the register at `:439`, and
`i2c_owner_init(..., 3072, ...)` at `NS2009.c:87` against the register at `:103`. A caller-argument
rule could compare them. They agree today (4096/4096 and 3072/3072), but nothing checks them. The
ratchet reasons now describe this correctly.

## INFO-3: the new kiln_nvs assertion does not pin the end() clear of the erases flag

`test_main_reset_fence.c:108`. `relay_authority_reset_set_erases_kiln_nvs(false)` is a no-op at this
point: the `in_flight_end()` just before it already cleared the flag at depth 0
(`relay_authority.c:258-260`). Because the test re-sets the flag explicitly, a mutant that removes
end()'s clear is masked. That would be a stale flag leaking into the next reset, the
reset-one-side class. In production, `relay_authority_reset_try_begin()` (`factory_reset.c:529`)
assigns the flag, so the masked path is narrow. If wanted, assert `!s_hook_kv("kiln_nvs")` once
directly after `in_flight_begin()` without calling the setter.

## INFO-4: `$stackNameAlias` has no staleness check

`:642-644`. If `recovery_exit_reboot` is renamed, the alias entry goes dead without any report. That
is harmless today, because the ratchet then flags the new skip. It is worth a one-line "every alias
key matched a create site" assertion.

## INFO-5 (tooling): `negtest.ps1 -Preset check` "loses the backslash" -- the Bash shell does it, not negtest

Confirmed. From the Bash tool, an unquoted `-PresetArg tools\check_stack_margin_registration.ps1`
reaches negtest as `toolscheck_stack_margin_registration.ps1`: Bash's quote removal drops the `\`
(`echo` shows the same). The run ends with
`NEGTEST ERROR: no such check: toolscheck_stack_margin_registration.ps1`. negtest's bare-name
fallback (`negtest.ps1:710-719`) then searches for that glued name.

The bare name (`-PresetArg check_stack_margin_registration.ps1`) works and was used for this review.
A single-quoted or forward-slash path also avoids the problem.

**Suggested fix:** when the bare name is not found, print a hint about Bash backslash quoting, or
accept `/` and document it in the header's `-Preset check` example (`:125-126`).
