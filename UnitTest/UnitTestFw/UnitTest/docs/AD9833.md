# AD9833 — Notes, defaults, and driver usage

Notes for the `AD9833` driver (programmable waveform generator, SPI).

Datasheet: `Datasheets/ad9833.pdf`

## Wiring

SPI, no MISO (write-only part) — CS/FSYNC is bit-banged by `spi_owner`
around each transfer rather than driven by the SPI peripheral's own CS,
since the owner needs to control chip-select timing across queued
transactions from multiple callers.

Pins, SPI host, and the MCLK crystal frequency are all
`idf.py menuconfig`-configurable — see `docs/HARDWARE.md`. **`MCLK_HZ` must
match the actual crystal/oscillator wired to the part's MCLK pin**; a wrong
value skews every programmed frequency, since the 28-bit frequency word is
computed as `round(freq_hz * 2^28 / MCLK_HZ)`.

## Driver APIs (primary)

- `AD9833_init(gen, host, sclk_gpio, mosi_gpio, cs_gpio, mclk_hz)` — brings
  up the SPI bus/device and the queueing owner task, then resets the part
  (held in reset, outputs disabled).
- `AD9833_reset(gen, hold)` — hold (`true`) or release (`false`) reset.
  Release once frequency/phase/waveform are programmed.
- `AD9833_set_frequency(gen, reg, freq_hz)` — programs `FREQ0` or `FREQ1`
  from a frequency in Hz. Rejects NaN/Inf and anything past Nyquist
  (`freq_hz > mclk_hz / 2`).
- `AD9833_set_phase(gen, reg, degrees)` — programs `PHASE0`/`PHASE1` from a
  phase in degrees (any value; normalized mod 360).
- `AD9833_select_freq_reg` / `AD9833_select_phase_reg` — selects which
  `FREQx`/`PHASEx` register the output actually uses.
- `AD9833_set_waveform(gen, waveform)` — `AD9833_WAVE_SINE` /
  `_TRIANGLE` / `_SQUARE` / `_SQUARE_DIV2`.
- `AD9833_sleep(gen, dac_power_down, mclk_power_down)` — independently
  powers down the on-chip DAC and/or the MCLK-driven core.

All of the above serialize against an internal mutex guarding the control
register's read-modify-write (`control_shadow`), so the driver is safe to
call from more than one task — important since it's driven both by the
firmware's boot-time init and by whatever task the UART bridge dispatches
commands from.

## Where to find the driver code

- `App/drivers/AD9833.h` / `App/drivers/AD9833.c`
- UART command bridge: `App/drivers/uart_bridge.c` (task 2, see
  `docs/UART_PROTOCOL.md` for the wire command format)
- Manual control from the PC: `pc_tools` GUI → `manualCtrl` → "AD9833
  Generator..."
