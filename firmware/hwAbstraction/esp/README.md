ESP-IDF backends for the KilnFW (ESP32-S3) build, one directory per
interface (spi/ i2c/ uart/ gpio/ kv/ time/ wdt/ pwm/ sysinfo/), plus the
board descriptor (board_kiln_s3.h).

Filled starting Phase 1a (move) / Phase 1b (adapt) of
docs/HW_ABSTRACTION.md. Empty as of Phase 0.

`gpio/hal_gpio_esp.c` (plus the shared `common/hal_esp_common.h/.c` esp_err_t->hal_status_t mapper) landed ahead of Phase 1a as bodies-only, not wired into any CMakeLists; syntax-checked by `firmware/hwAbstraction/test/compile_esp_backends.ps1`. There is no `adc/` backend here: hal_adc.h and docs/HW_ABSTRACTION.md both describe that interface as pico-only (wrapping SaftyFW's current_task.c/current_sense.c) with no ESP consumer, so a speculative `hal_adc_esp.c` written ahead of a real caller was removed -- see the plan's hal_adc section for the interface-mismatch findings it recorded before deletion.

`uart/hal_uart_esp.c`, `spi/hal_spi_esp.c` and `i2c/hal_i2c_esp.c` landed the same way (bodies-only, not wired into any CMakeLists, syntax-checked by the same script), grounded in espInterfaces/uart_owner.c, esp_spi_owner.c and i2c_owner.c: uart preserves the read-buffered-then-zero-wait `hal_uart_recv` fix and the two send primitives' wire-complete-vs-ring-drained split; spi reproduces the owner-task/heap slot-pool/wedge-latch/DMA-sentinel machinery with no dependency on drivers/owner_slot_pool.c; i2c preserves the static per-call semaphore and worker-enforced-timeout/unbounded-caller-wait behaviors plus the bus-reset-and-retry-once recovery. hal_uart.h and hal_i2c.h have no per-owner task-sizing fields (unlike hal_spi_bus_cfg_t), so both backends hardcode stack/priority/queue-length constants rather than widening the interface -- see the INTERFACE MISMATCH comments at the top of each file.

`wdt/hal_wdt_esp.c`, `pwm/hal_pwm_esp.c` and `sysinfo/hal_sysinfo_esp.c` landed the same way (bodies-only, syntax-checked by the same script), grounded in watchdog_cfg.c/factory_reset.c/ota_http_recovery.c (wdt), backlight_pwm.c's sole LEDC use (pwm), and dashboard_http.c/ui_page_diagnostics.c/partition_info_http.c/ota_http_esp.c/board_temps.c/safety_link.c/crash_report.c (sysinfo). hal_wdt_esp.c found one interface mismatch: this tree has no real `esp_task_wdt_init()` call site (the task-WDT is armed by IDF's own boot sequence from Kconfig, and watchdog_cfg.c only ever reconfigures it), so `hal_wdt_init()` is implemented as `esp_task_wdt_reconfigure()` rather than a fresh init -- see the INTERFACE MISMATCH comment at the top of hal_wdt_esp.c.

`kv/hal_kv_esp.c` and `time/hal_time_esp.c` landed the same way (bodies-only, syntax-checked by the same script), grounded in kiln_cfg_store.c/profiles_http.c/crash_report.c/boot_guard.c/factory_reset.c/ui_page_diagnostics.c (NVS) and the 44-site esp_timer_get_time()/vTaskDelay(pdMS_TO_TICKS()) census (time): kv implements `hal_kv_write_safe_here()` as the real `caller_stack_is_external()`/`esp_ptr_external_ram()` predicate and maps NVS-specific codes (`ESP_ERR_NVS_NOT_FOUND` et al.) locally since the shared `hal_esp_err_to_status()` mapper only covers the generic driver codes -- see the INTERFACE MISMATCH comment at the top of hal_kv_esp.c; hal_time_esp.c found no mismatch.
