Each zone reads one or more MAX31856 thermocouple channels -- pick which channels feed a zone below; when more than one is checked, the zone's control temperature is the average of that channel set's valid readings (thermo_combine.c). PID tuning lives here too, per the project's settled page layout. Calibration offset is stored here but not yet applied to live readings anywhere -- that's a separate, not-yet-built change to the readout path.

A running firing profile drives this zone's relay(s) toward its target using whichever control mode is selected below -- PID mode uses these Kp/Ki/Kd values, rendered onto the relay as a slow (1-minute) on/off duty cycle, not smooth proportional output: Kp sets how hard it reacts to the current temperature error, Ki corrects slow long-term drift (e.g. never quite reaching setpoint), Kd damps overshoot from reacting too fast. The max ramp rate below is what the Fire Profiles page checks a segment's ramp rate against before letting it save. Don't know good Kp/Ki/Kd numbers for this kiln? Use Autotune below instead of guessing.

Off by default (recommended): a guard trip on ANY zone aborts the whole firing, since the remaining zones would keep dumping heat into a chamber whose temperature is now partly unmeasured. Turn this on only if you deliberately want independent per-zone firings that don't take each other down.

The RP2040 safety processor reads its own, independent thermocouple -- a different physical sensor from any of the channels below. Set this to whatever type is actually wired into IT, not to match a zone; if the two ever disagree, the safety processor's temperature cross-check will disagree with the main board for no reason other than a wrong setting here.

PID Autotune

Step test (start here)

Runs an open-loop step test on one zone: holds heat off to settle, then applies a fixed duty and records the response until it looks settled or 4 hours pass. Fits a plant model from the response and proposes Kp/Ki/Kd (SIMC rule) -- nothing is written to the zone above until you click Accept. Owns that zone's relay(s) while running; refuses to start while a firing profile is running, and a firing profile refuses to start while this is running. Guard suite is fully armed during the test. This is a real heat test, not a simulation -- only run it with the kiln empty and attended.

Relay-feedback test (Åström–Hägglund) -- read this first

This test heats the kiln to a temperature you choose and then deliberately makes it oscillate around that temperature, over and over, for at least five full cycles. On a kiln one cycle is ten minutes or more, so the chamber spends hours swinging above and below your setpoint. That thermal cycling is hard on the ware -- anything in the kiln is being held at temperature and repeatedly heated and cooled, which is exactly what glaze and cone schedules are designed to avoid -- and it is hard on the elements, which age with every hot/cold cycle. Do not run it on a real firing, and do not run it at cone temperature. The step test above asks nothing like this of the kiln and also gives you a plant model, which this test does not.

What it measures: the ultimate gain and period (Ku, Tu) at the setpoint you pick, and proposes gains from them. It writes no plant model -- so if a step test already measured one for this zone, accepting a relay result leaves that model alone rather than replacing it. Guard suite is fully armed exactly as it is for the step test: any guard trip ends the run with the relays off. Aborts on its own if the zone can't reach the setpoint in 4 hours, or if it hasn't produced enough cycles within 4 hours of oscillating. The setpoint is refused if it is within 50 °C of this zone's max/min temperature limits, because the oscillation overshoots its band and would trip its own guard.

Honesty note, same as everywhere else on this page: this path has never completed on real hardware. The identification math is tested against a simulated plant; the on-target state machine that drives the relay has never seen a thermocouple, because this bench unit has none attached and every live autotune run so far aborts on the sensor guard within seconds.

Do the zones interfere? (Relative Gain Array)

Computed from the matrix above. Read only the bold diagonal: it is a score for "can this zone be controlled on its own?". 1.00 means yes -- what this zone's heater does to this zone's temperature doesn't change when the other zones are also regulating, so one independent PID per zone is the right thing and nothing more is needed. Numbers well above 1 mean the zones are propping each other up and each loop has to work harder than it thinks; negative means the neighbours' loops actually reverse this zone's response, and the zones would fight each other all firing. It is only computed over zones that have all their cross-gains measured, and it is refused outright rather than estimated when the matrix has a hole in it or is degenerate -- a wrong answer here would say "your zones are independent" about a kiln where they are not.
