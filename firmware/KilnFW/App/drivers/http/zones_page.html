Which tuning method should I use?

Tuning always runs on an empty kiln (autotune needs a clean, repeatable thermal response -- a load changes the mass the fitted model is measuring). Firing never is. The recommendation below is about which method's empty-kiln gains hold up once the kiln is loaded and fired -- not which method fits the empty-kiln data best on its own; a method that fits beautifully empty and drifts badly loaded is not the one to prefer. Basis for each recommendation is shown next to it: measured means the simulation campaign held out real runs at this temperature/load and checked the recommendation against them; extrapolated means this peak is past the simulator's checked range (see the boundary noted below) and the answer rests on assumed physics, not a checked run; indistinguishable means the campaign could not tell the two leading methods apart at this point and neither is picked.

Step test (start here)

Runs an open-loop step test on one zone: holds heat off to settle, then applies a fixed duty and records the response until it looks settled or 4 hours pass. Fits a plant model from the response and proposes Kp/Ki/Kd using the tuning rule picked below -- nothing is written to the zone above until you click Accept. Owns that zone's relay(s) while running; refuses to start while a firing profile is running, and a firing profile refuses to start while this is running. Guard suite is fully armed during the test. This is a real heat test, not a simulation -- only run it with the kiln empty and attended.

Relay-feedback test (Åström–Hägglund) -- read this first

This test heats the kiln to a temperature you choose and then deliberately makes it oscillate around that temperature, over and over, for at least five full cycles. On a kiln one cycle is ten minutes or more, so the chamber spends hours swinging above and below your setpoint. That thermal cycling is hard on the ware -- anything in the kiln is being held at temperature and repeatedly heated and cooled, which is exactly what glaze and cone schedules are designed to avoid -- and it is hard on the elements, which age with every hot/cold cycle. Do not run it on a real firing, and do not run it at cone temperature. The step test above asks nothing like this of the kiln and also gives you a plant model, which this test does not.

What it measures: the ultimate gain and period (Ku, Tu) at the setpoint you pick, and proposes gains from them. It writes no plant model -- so if a step test already measured one for this zone, accepting a relay result leaves that model alone rather than replacing it. Guard suite is fully armed exactly as it is for the step test: any guard trip ends the run with the relays off. Aborts on its own if the zone can't reach the setpoint in 4 hours, or if it hasn't produced enough cycles within 4 hours of oscillating. The setpoint is refused if it is within 50 °C of this zone's max/min temperature limits, because the oscillation overshoots its band and would trip its own guard.

Honesty note, same as everywhere else on this page: this path has never completed on real hardware. The identification math is tested against a simulated plant; the on-target state machine that drives the relay has never seen a thermocouple, because this bench unit has none attached and every live autotune run so far aborts on the sensor guard within seconds.

Tuning quality

One row per zone, read-only. Unknown means this zone has never been autotuned (or was hand-edited since), not that the fit was bad. Settled/Converged/Tau ok are the three fit-confidence flags autotune_engine_accept() gates acceptance on -- see the Autotune section above for what each means; a fit that reached DONE with one or more of these false can still have been accepted (with an explicit override), so seeing "no" here does not mean the currently-active gains are wrong, only that they came from a lower-confidence fit. Extrap. correction is how much of the fitted gain was extrapolated past the trace's own data rather than directly measured (rise at infinity minus the trace's raw last-sample rise) -- a large correction means a weaker fit even when every flag above reads yes.

Firing quality

Live while a firing is RUNNING (the numbers are still accumulating -- read them as "so far", not final) and frozen once it ends (DONE/FAULTED). Mean err is SIGNED: positive means this zone ran hot (above its ramp/dwell target on average), negative means it ran cold. Max over/under are separate figures on purpose -- a zone that overshoots on the way up and undershoots settling into a dwell has two different failure modes, not one "error", and averaging them together would hide both. IAE(norm) is the integral of absolute error, normalized by this run's own duration and setpoint span so a short profile and a 12-hour one -- or a 50°C bisque and a 300°C glaze firing -- produce comparable numbers; it is the one figure worth comparing ACROSS different profiles, which is the entire reason it exists. Ramp/dwell columns split the same mean/max error by which kind of segment the zone was in when it happened, since chasing a moving ramp target and holding a fixed dwell target are different jobs.

Do the zones interfere? (Relative Gain Array)

Computed from the matrix above. Read only the bold diagonal: it is a score for "can this zone be controlled on its own?". 1.00 means yes -- what this zone's heater does to this zone's temperature doesn't change when the other zones are also regulating, so one independent PID per zone is the right thing and nothing more is needed. Numbers well above 1 mean the zones are propping each other up and each loop has to work harder than it thinks; negative means the neighbours' loops actually reverse this zone's response, and the zones would fight each other all firing. It is only computed over zones that have all their cross-gains measured, and it is refused outright rather than estimated when the matrix has a hole in it or is degenerate -- a wrong answer here would say "your zones are independent" about a kiln where they are not.

Continuous Tuning (learn from firings)

A different thing from PID Autotune above: this runs no test of its own and applies no extra heat. When a zone is opted in here, every ORDINARY firing profile you run doubles as tuning data -- once a dwell segment settles, this quietly banks one (duty, steady-state rise) observation for that zone. At the END of a clean run (never during one -- see below), if enough good observations have piled up, it refits that zone's steady-state gain (K_dc), blends it a little at a time with the existing model, and recomputes Kp/Ki/Kd through the exact same SIMC rule Autotune's own Accept button uses. Off by default, per zone -- opting in is a deliberate choice, not something that starts on its own.

Safety property: gains are only ever changed at the very end of a run, after that zone's relay(s) are already off and it is no longer being actively controlled -- never mid-firing. A change here can never bump a firing that is currently in progress; the earliest it can affect anything is the NEXT time that zone fires.
