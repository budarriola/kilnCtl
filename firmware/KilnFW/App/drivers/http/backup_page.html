Backup & Restore

Export

Downloads a single JSON file: your saved fire profiles, plus every zone setting on the Thermocouples & Zones page -- PID gains, the fitted plant model, thermocouple type, name, relay/thermocouple assignment, calibration offset, max ramp ceiling, sanity-rate threshold, control mode, temperature limits, heater timing, and the guard-threshold overrides.

This file does NOT include Wi-Fi credentials (see Restore below for why).

It also includes every saved kiln configuration slot -- the named snapshots that let this controller be moved between kilns. Each one can still be downloaded and uploaded individually on that page instead, if you only need one. The web login password is never included, on either side.

Restore

Restoring OVERWRITES the profiles/zone-tuning fields named above with whatever the file contains -- an existing profile in the same slot ID is replaced. Wi-Fi credentials are never touched by this: a backup made on one board and restored onto another does not carry that first board's Wi-Fi network over, on purpose -- a kiln that changed physical location very likely also changed which Wi-Fi network it should join, and this page has no way to know whether that's true, so it never guesses. Set up Wi-Fi on the Wi-Fi page after restoring, same as on a brand-new board.

Restoring also brings in every kiln configuration slot the file contains, matched to your existing slots by identity, never by name. It never changes which kiln configuration is currently active. Two modes control what happens to slots on this board that are NOT in the file:

  • Merge (default, safer): slots only in the file are created here; slots only on this board are left alone.
  • Mirror: in addition to Merge's behavior, any slot on this board that is not in the file is deleted, so this board ends up holding exactly the file's set of kiln configurations.

Restore is refused outright (nothing is written) while a profile is running, the heaters are commanded on, or a firmware update is already in progress -- the same check this board's own OTA update uses before writing anything. The whole file is validated before any single field is written; a malformed or truncated upload changes nothing and reports why. Before anything is written, this page always previews the exact plan (every create, rename, and -- in Mirror mode -- delete, named) and asks you to confirm it.
