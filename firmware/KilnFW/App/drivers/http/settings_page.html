Reboot

Reboots both processors right now: this controller, and the safety processor, which is commanded to restart in place -- same firmware, same settings. This does not erase or change any configuration on either one -- zones, profiles, Wi-Fi credentials and saved settings are all left exactly as they are. Refused while a firing or autotune is running, or with any heater commanded on.

The safety processor can refuse on its own account (it will, if its heating relay is armed), and older safety firmware may not know this command at all. Either way this controller still reboots, and the message below reports what actually happened on each processor -- it will not claim the safety processor rebooted unless the safety processor said so.

This reboot will latch a safety trip, and does not clear one. While this controller resets, its fault line to the safety processor is undefined, which the safety processor reads as a main fault and latches as S6a (SAFETY_TRIP_MAIN_FAULT). Expect that trip every time -- rebooting the safety processor as well does not avoid it, because the RP2040 comes back long before this controller does and re-latches on the still- undefined line. That is correct fail-safe behaviour, not a fault in the board, and nothing on this path sends a clear.

Required follow-up before heating: clear the latched trip with Clear latched trip on the Safety page (or the dashboard's Clear Trip button) -- both POST /api/safety/clear_trip. Heat stays blocked until you do. No JTAG is needed for that, and never was. Until the trip is cleared, starting a firing is refused, naming this trip as the reason -- see the Readiness page.

Danger zone

Each button below erases ONLY what it says and reboots the board immediately -- there is no undo. "Wi-Fi" never touches zones/rules/profiles; "kiln config" never touches Wi-Fi or profiles; "profiles" never touches anything else. "Factory default" erases all three, and also reformats the config filesystem (the `cfg` partition zones/profiles/preferences are migrating onto).

Login credentials are not included in any of these buttons, "Factory default" included -- clear them either from Security settings's own "Clear login credentials" action, or via the physical four-corner E-stop-gated reset gesture at the panel.

Config filesystem did not mount. Formatting will erase it. Only confirm this if you do not recognize this board's config history (e.g. it was flashed from someone else's image) -- otherwise investigate before erasing.
